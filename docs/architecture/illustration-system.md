# ILLUSTRATION SYSTEM

**Statut** : Référence officielle du langage des illustrations de Mentora. Sixième descendant officiel du [MENTORA DESIGN SYSTEM FOUNDATION](mentora-design-system-foundation.md).
**Portée** : Architecture fonctionnelle uniquement. Aucune illustration, aucun dessin, aucun personnage, aucune mascotte, aucun style graphique, aucune palette, aucune référence Figma, aucune IA générative, aucun prompt, aucun SVG, aucun code. Ce document définit **le langage officiel des illustrations** ; il traduit le pilier **Illustration** de la fondation ; les illustrations concrètes seront produites plus tard — jamais ici ; les Tokens arriveront en P11.8, le Flutter Design Kit en P11.9.
**Préséance** : P9 → P10 → [Accessibility Foundation](accessibility-foundation.md) (**opposable**) → [Global Experience Foundation](global-experience-foundation.md) (**opposable**) → P11.0 → ce document (DSD-01 : il précise, il ne redéfinit rien). Il respecte le [Color System](color-system.md), le [Typography System](typography-system.md), le [Spacing System](spacing-system.md), l'[Elevation & Surface System](elevation-surface-system.md) et l'[Iconography System](iconography-system.md) sans jamais redéfinir leurs règles.
**Niveaux produits (DSD-02)** : Principles et Standards (§7) ; les Tokens et Implementations viendront de P11.8 et P11.9.
**Transversalité (DSD-03)** : ce système sert Identity (l'illustration incarne le calme, la sobriété professionnelle, l'intemporalité) et Documentation (chaque contexte illustré est traçable jusqu'à sa règle amont, §6).
**Continuité (MSD-02)** : un contexte illustré garde son sens à travers toute interruption — et son contenu survit sans image (§11, Voice) : la narration porte le même contexte.

---

## 1. Mission

**Une illustration n'est jamais une décoration.**

Une illustration **explique. Rassure. Accompagne. Contextualise. Humanise.**

Elle **ne distrait jamais**. Elle **ne cherche jamais à divertir**. Elle **n'existe jamais pour remplir un vide**.

**Principe fondateur** :

> **« Une illustration explique une situation professionnelle. Jamais une page. »**

---

## 2. Vision

| Règle | Énoncé |
|---|---|
| ILV-01 | Chaque illustration possède **une responsabilité officielle. Jamais plusieurs** (MSV-04). |
| ILV-02 | **Jamais une illustration gratuite. Jamais une illustration marketing. Jamais une illustration « Dribbble ». Jamais une illustration à la mode** (DPV-03, DST-05). |
| ILV-03 | Une illustration existe **parce qu'elle aide l'expert à comprendre son contexte** — sinon elle n'existe pas. |
| ILV-04 | Toute illustration s'attache à une situation officielle (§5, §8) ; une illustration sans situation n'existe pas (DSG appliqué). |

## 3. Les dix piliers

Dix piliers. Toute règle d'illustration appartient à exactement un pilier.

### 3.1 Professional Illustration

| | |
|---|---|
| **Mission** | Faire que l'illustration respecte le monde professionnel — Mentora est un outil de travail. |
| **Responsabilités** | Tenir le registre : **jamais caricaturales, jamais enfantines, jamais ludiques gratuitement** (DPV-08 : l'expert travaille, il ne joue jamais) ; la sobriété du Professional Tone appliquée à l'image. |
| **Frontières** | Le registre émotionnel permis vient du Design Language (Emotional Tone : sérénité, gravité mesurée, reconnaissance sobre) ; le style concret viendra des Tokens sous ces principes. |
| **Ce qu'il garantit** | un expert de n'importe quel âge et n'importe quel métier se sent respecté par l'image. |
| **Ce qu'il ne possède jamais** | une mascotte ; un gag ; un style de mode. |

### 3.2 Context Illustration

| | |
|---|---|
| **Mission** | Faire que l'illustration explique **une situation. Jamais un écran.** |
| **Responsabilités** | Définir les situations légitimes : *pas de consultation aujourd'hui, profil incomplet, paiement en attente, aucune donnée disponible, connexion interrompue, première utilisation* — chaque situation officielle, publiée par sa plateforme. |
| **Frontières** | La situation est un fait publié ; l'illustration la rend humaine, elle ne la crée pas ; un écran n'est jamais une situation (le principe fondateur). |
| **Ce qu'il garantit** | l'image dit toujours « voilà où tu en es » — jamais « voilà une jolie page ». |
| **Ce qu'il ne possède jamais** | la situation elle-même ; une illustration d'habillage permanent. |

### 3.3 Empty States

| | |
|---|---|
| **Mission** | Donner un visage au vide — **jamais triste : calme.** |
| **Responsabilités** | Définir l'illustration des états vides conçus (EV du Home) : **ils expliquent, ils invitent à agir, ils ne culpabilisent jamais** ; **le vide est assumé, jamais masqué** (EV-03, EV-04). |
| **Frontières** | L'état vide est publié ; l'illustration l'accompagne avec son texte (rôle Empty State du Typography System) — jamais seule. |
| **Ce qu'il garantit** | « rien ne demande votre attention » se ressent comme une bonne nouvelle — pas comme un échec. |
| **Ce qu'il ne possède jamais** | un vide meublé ; une tristesse ; un reproche. |

### 3.4 Learning Illustration

| | |
|---|---|
| **Mission** | Faciliter la compréhension d'un nouveau parcours — puis s'effacer. |
| **Responsabilités** | Définir l'illustration d'apprentissage : elle éclaire un parcours à sa découverte ; **elle disparaît dès que l'utilisateur maîtrise ce parcours** (ILE-02) — l'aide n'est jamais un meuble. |
| **Frontières** | Le parcours appartient à la navigation ; le moment d'apprentissage à l'expérience ; l'illustration accompagne, à durée de vie bornée. |
| **Ce qu'il garantit** | le débutant est guidé, l'expert confirmé n'est jamais encombré. |
| **Ce qu'il ne possède jamais** | une présence permanente ; un tutoriel obligatoire. |

### 3.5 Guidance Illustration

| | |
|---|---|
| **Mission** | Guider — accompagner, préparer, rassurer. |
| **Responsabilités** | Définir l'illustration de guidage : elle accompagne un moment délicat (préparation, premier acte protégé, reprise), elle prépare et rassure — **jamais elle ne remplace une explication** (ILT-07 ; le texte explique, l'image accompagne — ICA-01 étendu). |
| **Frontières** | L'explication appartient au texte (Typography) ; la protection à l'Interaction Foundation ; l'illustration adoucit sans rien décider. |
| **Ce qu'il garantit** | le moment difficile est humain — et l'information complète reste dans le texte. |
| **Ce qu'il ne possède jamais** | une information exclusive ; un contournement d'explication. |

### 3.6 Trust Illustration

| | |
|---|---|
| **Mission** | Faire que l'image respecte la confiance. |
| **Responsabilités** | Tenir les interdits : **jamais elles n'exagèrent, jamais elles ne promettent, jamais elles ne manipulent** (DT-03, DT-05 appliqués à l'image) ; une illustration n'embellit jamais un fait au-delà de ce qu'il est. |
| **Frontières** | Les faits appartiennent aux plateformes ; l'image les accompagne sans les amplifier (Emotional Tone : jamais d'amplification). |
| **Ce qu'il garantit** | aucune image ne vend, aucune image ne survend : ce que l'image suggère, le produit le tient. |
| **Ce qu'il ne possède jamais** | une promesse visuelle ; un effet marketing (ILG-03). |

### 3.7 Accessibility Illustration

| | |
|---|---|
| **Mission** | Faire que l'image n'exclue jamais. |
| **Responsabilités** | Porter l'exigence opposable : **une illustration n'est jamais porteuse d'une information essentielle ; toute information reste disponible par le texte** (AFI-04) ; l'image est un accompagnement — sa disparition ne retire aucun sens. |
| **Frontières** | Les alternatives concrètes appartiennent aux Tokens/Implementations sous ces contraintes ; l'Accessibility Foundation prévaut (AFR-02). |
| **Ce qu'il garantit** | qui ne voit pas l'image ne perd rien — jamais. |
| **Ce qu'il ne possède jamais** | une information exclusive à l'image ; un sens perdu sans elle. |

### 3.8 Global Neutrality

| | |
|---|---|
| **Mission** | Faire que le monde entier puisse s'y reconnaître. |
| **Responsabilités** | Porter l'exigence internationale (GE-09) : **aucun vêtement local, aucun monument, aucun drapeau, aucune religion, aucune ethnie privilégiée, aucun humour régional, aucun geste culturel** ; la représentation humaine, quand elle existe, est plurielle ou abstraite — jamais un « type » par défaut. |
| **Frontières** | L'Illustration respecte intégralement la Global Experience Foundation (opposable) ; un doute culturel se résout par l'abstraction — ou par l'absence d'image. |
| **Ce qu'il garantit** | un expert de Bamako, Tokyo ou Copenhague se reconnaît — ou du moins ne se sent jamais étranger. |
| **Ce qu'il ne possède jamais** | une culture de référence ; un symbole à double lecture. |

### 3.9 Illustration Relationships

| | |
|---|---|
| **Mission** | Faire que toutes les illustrations parlent le même langage. |
| **Responsabilités** | Tenir l'unité : **jamais des styles concurrents, jamais des équipes différentes** (DSC-04) ; une seule grammaire visuelle d'illustration, cohérente avec l'Iconography (les deux vocabulaires se répondent sans se confondre). |
| **Frontières** | La grammaire concrète appartient aux Tokens ; ce pilier fixe la loi d'unité. |
| **Ce qu'il garantit** | deux illustrations de Mentora sont toujours sœurs — jamais étrangères. |
| **Ce qu'il ne possède jamais** | un style local ; une collection hétéroclite. |

### 3.10 Future Evolution

| | |
|---|---|
| **Mission** | Accueillir demain — **le style graphique pourra évoluer. Jamais la philosophie.** |
| **Responsabilités** | Porter le protocole : une évolution de style est une décision de système (Tokens révisés) qui préserve toutes les règles de ce document ; une nouvelle situation illustrable naît d'un contexte publié et entre dans une famille (§8). |
| **Frontières** | L'évolution passe par la gouvernance (§12) ; jamais par une image isolée « en avance ». |
| **Ce qu'il garantit** | dans dix ans, les images auront peut-être changé de trait — jamais de raison d'être. |
| **Ce qu'il ne possède jamais** | une mode ; une exception précurseur. |

## 5. Relations avec les plateformes

**Principe majeur** :

> **« Une illustration disparaît lorsque l'expert commence réellement à travailler. »**

Les illustrations servent : **les premiers pas, les états vides, la découverte, la pédagogie, certaines transitions.** Elles disparaissent **au profit des données et des actions.**

| Plateforme | Où l'illustration est légitime | Où elle devient inutile |
|---|---|---|
| Home | la journée calme (état vide), le premier accès | dès qu'une remontée existe : les cartes d'intention priment |
| Consultation | l'agenda vide, la découverte du cycle, la préparation rassurée | l'agenda rempli, la Salle Live (jamais d'illustration en séance), le résumé |
| Business | les premiers revenus à venir (aucune activité), la découverte des objectifs | dès qu'un chiffre existe : les données priment, jamais une image à côté d'un montant |
| AI | la découverte du copilote, l'absence de proposition (calme assumé) | dès qu'une proposition existe : la proposition prime |
| Reputation | le profil naissant, le premier avis attendu | dès que les preuves existent : les preuves priment |
| Account | le premier accès, l'environnement en ordre (« aucune action nécessaire ») | la sécurité (jamais d'illustration sur une alerte), les réglages remplis |

| Règle | Énoncé |
|---|---|
| ILPL-01 | Même langage d'illustration partout — aucune plateforme n'a son style (DR-01). |
| ILPL-02 | L'illustration cède toujours la place au travail : donnée présente > image (le principe majeur). |
| ILPL-03 | Jamais d'illustration en immersion (Salle Live) ni sur une alerte de sécurité. |
| ILPL-04 | Toute nouvelle plateforme reçoit le langage tel quel (DSR-04). |

## 6. Traduction du MES — les règles traduites

Chaque règle traduit une règle amont, citée explicitement. **Une traduction ne modifie jamais la règle** (DSM-02).

| Règle amont traduite | Traduction illustration |
|---|---|
| Design Language — DPV-03/DPV-08 (bruit éliminé, jamais de jeu) | Professional Illustration (§3.1) ; ILV-02 : jamais gratuite ni à la mode |
| Design Language — Emotional Tone (registres permis/interdits) | le registre des images : sérénité, gravité mesurée, jamais de culpabilisation |
| Design Language — EV-03/EV-04 (vide assumé, jamais meublé) | Empty States (§3.3) |
| Interaction Foundation — IE-02 (jamais culpabiliser) | les états vides et erreurs illustrés sans reproche |
| Motion Foundation — MV-04 (le mouvement explique) | une illustration animée uniquement au service d'une intention du mouvement — jamais pour vivre |
| Navigation Foundation — Recovery/NCO | la famille Recovery (§10) : la reprise humanisée, jamais dramatisée |
| Accessibility Foundation — AFI-04 | Accessibility Illustration (§3.7) : l'image jamais porteuse d'essentiel, opposable |
| Responsive Foundation — RSE-01 (plus d'espace ≠ plus de contenu) | plus d'espace n'ajoute jamais d'images ; l'illustration ne remplit pas |
| Global Experience Foundation — GE-09 | Global Neutrality (§3.8) |
| Component Foundation — familles d'intention | l'illustration vit dans les composants d'état (Empty State, premiers pas) — jamais en électron libre |
| Color System — rôles d'environnement et sémantiques | les images respectent les rôles : jamais une couleur signifiante détournée en décor |
| Typography System — Empty State/Hint (le texte explique) | Guidance (§3.5) : l'image accompagne le texte, jamais l'inverse |
| Spacing System — Information Breathing | une image a son air ; elle ne comprime jamais le contenu utile |
| Elevation & Surface — Content Containment | une illustration vit dans sa surface d'intention ; jamais en pleine page par-dessus le travail |
| Iconography System — ICA (le signe accompagne le texte) | la même loi d'accompagnement, à l'échelle de l'image |

| Règle | Énoncé |
|---|---|
| ILM-01 | Toute règle cite son origine amont (DSM-01) ; une règle sans origine est rejetée. |
| ILM-02 | Un manque découvert face à une règle amont remonte en révision — jamais comblé par une image improvisée (DSM-03, GE-15). |

## 7. Les niveaux

Six niveaux — la production descend toujours (DSL-01) :

| Niveau | Mission | Responsabilités | Contient | Ne contient jamais |
|---|---|---|---|---|
| **Identity** | l'image comme personnalité | relier l'illustration aux 8 qualités (calme, sobre, intemporelle) | les principes identitaires de l'image | un style ; un trait |
| **Semantic** | les situations | le registre officiel : situation ↔ contexte publié | les situations nommées, légitimes et interdites | un écran illustré ; une situation inventée |
| **Narrative** | ce que l'image raconte | la narration de chaque situation (ce qu'elle explique, rassure, invite) — la même narration nourrit le Voice (§11) | les intentions narratives par situation | une promesse ; un drame ; une information exclusive |
| **Component** | l'image en situation | l'application par famille de composants (états vides, premiers pas) | les règles d'application par famille | une image hors composant ; une exception |
| **Token** | les images nommées | (produit par P11.8) chaque situation reçoit sa référence de style et d'asset | la nomenclature situation → image | une situation nouvelle |
| **Implementation** | l'image dans la technologie | (produit par P11.9) la consommation fidèle | le code des kits | une image hors registre ; un écart |

## 8. Les familles officielles

Douze familles. **Les familles expriment des contextes. Jamais des écrans.** Toute illustration appartient à exactement une famille.

| Famille | Contexte exprimé |
|---|---|
| **Welcome** | l'arrivée : Mentora se présente, sobrement |
| **Onboarding** | la mise en place guidée du premier accès |
| **Empty State** | le vide assumé et calme, par situation publiée |
| **Learning** | la découverte d'un parcours — à durée de vie bornée (§3.4) |
| **Guidance** | l'accompagnement d'un moment délicat |
| **Business** | les contextes économiques naissants (aucune activité, premiers objectifs) |
| **Consultation** | les contextes du cycle naissant (agenda vide, découverte de la préparation) |
| **AI** | la découverte du copilote ; le calme sans proposition |
| **Trust** | les contextes de confiance naissante (profil à construire, première preuve) |
| **System** | l'environnement : connexion interrompue, maintenance annoncée |
| **Attention** | l'accompagnement humain d'une attention non critique — jamais la sécurité (ILPL-03) |
| **Recovery** | la reprise sereine après interruption — le contexte retrouvé |

| Règle | Énoncé |
|---|---|
| ILF-01 | Une illustration par famille, une famille par illustration ; toutes sœurs (Illustration Relationships). |
| ILF-02 | Une nouvelle famille exige la révision de ce document — jamais une collection parallèle. |

## 9. Les états

| Moment | Règle |
|---|---|
| **Quand une illustration apparaît** | uniquement quand sa situation officielle est publiée (vide, premier accès, découverte, interruption système) — jamais par défaut, jamais pour habiller. |
| **Quand elle disparaît** | dès que la situation cesse : la donnée arrive, le parcours est maîtrisé (Learning), l'action commence — **une illustration disparaît lorsque l'expert commence réellement à travailler** ; sans trace fantôme (DIS-05). |
| **Quand elle évolue** | uniquement par décision de système (§3.10) — jamais localement, jamais par écran. |
| **Quand elle ne doit jamais être affichée** | en immersion (Salle Live) ; sur une alerte de sécurité ; à côté d'un montant ; à la place d'une donnée due ; pendant un acte protégé. |

| Règle | Énoncé |
|---|---|
| ILE-01 | **Une illustration ne doit jamais ralentir le travail** — ni en temps (MT-01), ni en place (elle cède au contenu utile), ni en attention (Focus). |
| ILE-02 | L'illustration d'apprentissage a une fin : la maîtrise du parcours la retire (§3.4). |
| ILE-03 | L'apparition et la disparition suivent les intentions du mouvement (Entrance/Exit) — sobrement. |

## 11. Mobile First et extensibilité

### 11.1 Mobile First

| Règle | Énoncé |
|---|---|
| ILMF-01 | **Une illustration reste lisible sur téléphone** — ou n'existe pas (DSMF-03). |
| ILMF-02 | **Elle ne prend jamais la place du contenu utile** : sur petit écran, le travail d'abord. |
| ILMF-03 | **Elle disparaît si elle gêne l'action** — sans regret, sans exception. |

### 11.2 Extensibilité — pensé pour dix ans

| Extension | Comment elle s'insère |
|---|---|
| Pliables, tablettes, desktop | mêmes situations, présentation adaptée — plus d'espace n'ajoute jamais d'images (RSE-01) |
| TV | les contextes lisibles à distance ; toujours moins d'images, jamais plus |
| Wearables | aucune illustration : l'essentiel seulement — le contexte passe par le texte |
| Réalité mixte | les situations gardent leurs lois ; l'espace n'est jamais un prétexte à décor |
| **Voice** | **une illustration devient une narration** : la situation s'explique par la parole — **elle est remplacée par une explication, jamais par un effet sonore** ; **le même contexte doit survivre sans image** — c'est le niveau Narrative (§7) qui garantit cette équivalence : la narration de chaque situation est définie avant son image |
| Nouveaux appareils | le protocole Future Evolution (§3.10) |

| Règle | Énoncé |
|---|---|
| ILX-01 | Les dix piliers (§3), les douze familles (§8) et les six niveaux (§7) sont l'invariant décennal. |
| ILX-02 | **Le style graphique pourra évoluer. Jamais la philosophie.** |
| ILX-03 | Aucune extension ne peut affaiblir l'Accessibility Illustration (§3.7) ni la Global Neutrality (§3.8) — les deux opposables. |

## 13. Gouvernance du document

- Ce document est la **référence officielle** du langage des illustrations de Mentora — sixième descendant du Design System, traduisant le pilier **Illustration**.
- **Conformité aux fondations opposables** : l'Accessibility Foundation est servie par Accessibility Illustration (§3.7 — l'image jamais porteuse d'une information essentielle, tout reste disponible par le texte, la disparition de l'image ne retire aucun sens) et opposable à tout arbitrage (AFR-02, ILX-03) ; la Global Experience Foundation est servie par Global Neutrality (§3.8 — aucun vêtement local, monument, drapeau, religion, ethnie privilégiée, humour régional ou geste culturel ; représentation plurielle ou abstraite) et opposable de même (GE-15).
- Toute vague d'implémentation cite le pilier, la famille, le niveau, l'état et les règles (ILV/ILP/ILN/ILPL/ILM/ILF/ILE/ILT/ILMF/ILG/ILX) qu'elle réalise.
- Toute modification de ce document est une décision d'architecture explicite, tracée, jamais un effet de bord d'une vague d'implémentation.
- En cas de conflit : P9.0 prévaut, puis P10, puis les fondations opposables (Accessibility, Global Experience), puis le [MENTORA DESIGN SYSTEM FOUNDATION](mentora-design-system-foundation.md), puis ce document (DSD-01).
