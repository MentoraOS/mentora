# F3.2.99 — Grand Tactical Constitutional Audit

> État **final ratifié**. Le Grand Audit juge l'ensemble du modèle tactique des
> quinze domaines et fait naître la loi **R-C**.

## 1. Reconstruction totale depuis la feuille blanche

Les dix besoins fondamentaux redécomposés en vérités, chaque vérité soumise au sextuple test (NON, invariant, constat, commande, lecture, garde), **sans regarder les frontières existantes**. Résultat : *identité* se scinde en trois NON irréductibles (ce que je déclare / ce que les faits prouvent / ce qui prouve que j'entre) ; *rencontre* en deux (la promesse / le vécu) ; *confiance* rejoint la preuve ; *argent* en deux (le sens / le transport) ; *collaboration* en deux (le lien / le dialogue) ; *contenu* en deux (la production de la machine / la garde de la matière) ; *consentement* résiste à toute décomposition ; *communication* en deux (le dialogue / le signal) ; *plateforme* en deux (la personne et ses choix / l'intérêt du client) ; *stockage* reste un. **La feuille blanche reconverge exactement sur quinze vérités — les quinze domaines.** La convergence indépendante est la plus forte démonstration de minimalité.

## 2. Minimalité des quinze

Chacun soumis aux six questions : *disparaître ?* — aucun (chaque disparition rend une vérité orpheline) ; *fusionner ?* — les onze fusions historiques re-mortes (deux NON, un domaine) ; *se découper ?* — les découpes tentées re-mortes (une vérité, deux registres) ; *vérité, NON, invariants propres ?* — quinze fois oui. **Minimal, démontré.**

## 3. Les quinze frontières stratégiques — rejouées

Aucune vérité ne traverse un mur (les traversées sont des personnes) ; aucun NON partagé (le double NON d'Enterprise est *dans* un domaine) ; aucune commande illégale. Cas les plus attaqués, tenus : Engagement↔Consultation (le cycle « honoré » reste mort), Augmentation↔Storage (la faille d'adoption close), Account↔Identity & Access, Economy↔Consultation. **Quinze frontières définitivement démontrées.**

## 4. Recensement des unités — trente, jugées

Le recensement final par domaine : Discovery 1 (`ClientInterest`) · Professional Identity 3 (`ProfessionalIdentity`, `Offer`, `SpecialtyRegistry`) · Engagement 1 (`Agreement`) · Consultation 2 (`Encounter`, `FollowUp`) · Reputation 4 (`Review`, `CertificationRecord`, `AchievementRecord`, `AudienceMeasurement`) · Account 4 (`Account`, `AvailabilityFrame`, `Subscription`, `SupportRequest`) · Enterprise 5 (`Organization`, `Invitation`, `Membership`, `Sponsorship`, `OrganizationVerification`) · Consent 1 (`ConsentLedger`) · Messaging 1 (`Conversation`) · Economy 2 (`FundsLedger`, `Goal`) · Augmentation 1 (`Production`) · I&A 2 (`Credential`, `Session`) · Settlement 1 (`SettlementOrder`) · Notification 1 (`Signal`) · Storage 1 (`Deposit`).

> **Compte : 30 unités** (1+3+1+2+4+4+5+1+1+2+1+2+1+1+1). *La source du Grand Audit écrivait « 25 » ; F3.3 §14 corrige ce total à 30 — l'énumération fait foi, jamais le chiffre écrit à la main (amendement rejoué).* Chacune re-testée : trop grande ? (ConsentLedger, FundsLedger — leurs frontières SONT leurs invariants : porte close, somme) ; trop petite ? (Goal — immuable, sans lien de somme) ; sans NON ? aucune ; **manquante ?** — Readiness (outillage), gouvernance du Référentiel (actes du `SpecialtyRegistry`), Effacement (Process) : **aucune manquante**.

## 5. Toutes les interactions — la naissance de R-C

Aucune Command ne traverse ; chaque Event a son constatant ; les projections tenues en lecture ; **zéro Domain Service dans les quinze domaines**.

**LE COUP PORTÉ — la règle de lecture manquante.** En rejouant les Queries, le Conseil a constaté que le droit de lire était écrit pour certaines (`ConversationQuery` — l'Interlocuteur seul) et **implicite pour d'autres** (`AvailableFundsQuery` — qui a le droit de lire l'argent d'un expert ?). Une lecture sans ayant droit nommé est une porte ouverte en devenir.

## 6–8. Invariants, langage, chronologies

Invariants : aucun partagé, dupliqué, sans gardien, ni dans un Repository/Service/Projection/Query ; *les sommes exigent des frontières, les identités exigent des clés* re-testé sur les six candidats R-A. Langage : cinq mots du refus à leur place, huit réservations respectées, aucun mot interdit. Chronologies : quinze machines rejouées, aucun état mort, aucune transition silencieuse, aucun terminal réversible.

## 9. Provenances — deux précisions

Chaînes re-testées (toutes ✓) ; **deux précisions rendues, cohérentes avec les dessins** : *`Deposit ← Artifact`* — le sens est inverse : l'Artifact cite SON Dépôt ; le Dépôt cite son Commanditaire et son ordre (aucune garde ne connaît le métier de ce qu'elle garde) ; *`Payout ← Encounter`* — le Retrait ne cite aucune rencontre : la chaîne d'argent passe par les faits de reconnaissance (`RevenueSource: EncounterId`) puis la somme ; le Retrait cite le Ledger et sa demande, l'audit remonte par les revenus. Aucune copie mutable, aucune jointure obligatoire.

## 10. R-A et R-B — champs d'application complets

R-A testée sur les six clés (argent — unicité de reconnaissance ; créneaux ; abonnements ; appartenances ; reconnaissances ; ordres) : aucune clé illégale (aucune ne porte de règle ; la somme, elle, en frontière). R-B testée sur les onze unités à terminal : aucun terminal qui devrait rouvrir (le regret : UX-06 ; le réessai : provenance), aucune unité nouvelle inutile, aucun terminal oublié.

## 11. Dix architectures concurrentes — dix destructions

*Transaction Script · Active Record · Rich Domain Services · Actor Model · CRUD · Event Sourcing Everywhere · CQRS Everywhere · Microservices First · Database First · Workflow Engine First* — dix reconstructions, dix destructions, **toujours par les deux seules morts possibles : un propriétaire sans NON, ou deux NON pour une vérité.**

# R-C — Ayant droit de lecture (loi tactique, née ici)

> **R-C — Structural Read Right.** *Toute Query publiée nomme son ayant droit ; une lecture sans droit est refusée comme une commande — motivée.*

Application immédiate (la grille complète — Query Catalogue — vit au chapitre 06, F3.3 §5) : `AvailableFundsQuery` → le Titulaire (et l'outillage de conformité) ; `ConsentValidityQuery` → tout domaine agissant, **pour son propre acte seulement** (la loi anti-profilage devient un droit de lecture) ; `MembershipQuery` → l'Organisation et le Membre ; `AgreementStateQuery` → les parties ; les registres publics (Référentiel, Offres publiées) → tous. Erreur classique réfutée : « c'est juste une lecture » — **une lecture est un contrat**.

R-C rejoint **R-A** (le registre applique une clé déclarée, ne juge pas) et **R-B** (après terminal, une unité nouvelle à provenance citée) : le triptyque tactique du registre. *(Édition consolidée des trois lois : chapitre 06, F3.3 §10.)*

## 12. Décision constitutionnelle

*Meilleur découpage ?* NON (la feuille blanche reconverge). *Des Aggregates ?* NON (trente unités, chacune démontrée trois fois). *Meilleur langage ?* NON. *Meilleur placement des invariants ?* NON. *Meilleur propriétaire des faits ?* NON (73 constatants uniques). *Meilleure architecture tactique globale ?* NON (dix concurrentes détruites).

Sont déclarés définitivement gelés : les 15 Domaines, toutes les frontières, les 30 Aggregates, toutes les Policies, Specifications, State Machines, interactions, provenances, les règles R-A et R-B, tout le langage tactique — avec les trois consolidations du Grand Audit, immédiatement constitutionnelles : **R-C** (toute Query nomme son ayant droit), les deux précisions de provenance, et la liste close des ratifications dues au gel documentaire (`FundsLedger`, grille R-C, capacité d'invitation différée).

> **F3 — Domain Tactical Design est définitivement ratifié et devient la Constitution tactique officielle de Mentora.**
